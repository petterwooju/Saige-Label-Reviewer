## 自动化验证层

### 轻量 CI

CI 在 `windows-latest` + Python 3.12 上运行，只安装固定版本的 NumPy、Pillow、scikit-learn 和 SciPy，然后执行：

```powershell
python -m unittest discover -s tests -v
python -m compileall -q src tests run.py
node --check src/saige_reviewer/static/app.js

$tokens = $null
$parseErrors = $null
[System.Management.Automation.Language.Parser]::ParseFile(
  (Resolve-Path 'setup.ps1'), [ref]$tokens, [ref]$parseErrors
) | Out-Null
if ($parseErrors.Count) { throw 'setup.ps1 contains PowerShell syntax errors' }
```

CI 刻意不安装 Torch/transformers/umap-learn，不访问 Hugging Face，不下载模型。它用于检查轻量单元/集成性质、Python 编译、前端 JavaScript 语法和 setup PowerShell AST 可解析性，不是真实 DINOv2 验收。报告应使用测试运行时实际发现的用例数，不在文档或工作流中固定总数。

开发者在运行 `setup.ps1` 后还应运行同一测试套件，确认依赖与硬件特定的测试实际执行而非跳过。报告时要列出“通过/失败/跳过”，不将跳过项计为通过。

### 必要自动化性质

- 真实适配器载入项的分数/建议为空，状态为 `not_analyzed`；演示项为 `demo`。
- 目录指纹对图像内容变化敏感，即使 size/mtime 被伪装也不得复用。
- 未授权绝对路径和 `..` 越界路径被拒绝；明确授权的附加根可以读取。
- 严格 JSON 在任意层级拒绝 `NaN`/`Infinity`、溢出为非有限 float 的数字、重复键和过深嵌套；数字字符串坐标和边界加法也必须保持有限。
- srproj 重复最终显示名和 Saige 同名类别的 `classId`/`classColor` 冲突被拒绝；不安全结构类型不得被默默纠正。
- 文件夹根图像，以及数据集根内条目中的符号链接、Windows 目录联接和非普通文件系统对象被拒绝；visionproj 重复条目名、带数据的目录条目和多个有效项目 manifest 被拒绝。
- 模型 revision 必须是完整 40 位哈希；`local_only` 缺模型时在推理前失败，`download_if_missing` 只在明确选择时传入。
- Hugging Face 模型身份包含当前 revision 缓存的 `config.json` 和 `model.safetensors` 各自大小/SHA-256；缺失任一文件或加载期间身份变化会停止分析。
- setup 标记保存模型配置/权重大小和 SHA-256；标记写入后完整自检精确依赖、模块导入、PyTorch 变体/GPU 和未跳过时的模型文件，任一失败都删除标记。
- 缓存身份对应用/算法/schema、模型文件内容、关键依赖、设备/精度、原始标签、源内容和外部图像内容变化敏感。
- 缓存 ZIP/NPY 预检拒绝多余/缺失/重复条目、过大头部/负载、不安全 dtype、错误 shape 和文件竞争；数组内容还必须验证有限性与数值范围。
- 缓存复用前、特征提取后和缓存保存后的外部变化均使任务失败，新写缓存被删除。
- 分析完成后替换 srproj/Saige JSON 的外部预览图像时，下一次预览必须清空整批旧分析字段、坐标和 job provenance，返回一次性 stale 诊断并让前端刷新后持久提示重跑；人工复查状态保持不变。
- 分析规模预检对特征矩阵和 `N×C` 评分工作矩阵各使用 512 MiB 保护预算，实际特征维度变大时在分配前再拒绝；`t-SNE` 超过 50,000 项在推理前失败，UMAP 不受该 t-SNE 上限影响。
- ROI 覆盖越界、反向、完全位于图像外、NaN/无穷、结构错误与无效轮廓；无效 ROI 退化为整图。
- `analyze` 不原地修改数据集；完整 `item_updates` 在锁内原子写回，不完整/无效批次零部分生效，旧会话 worker 无法污染新会话。
- `/api/job` 不返回 items/full session；人工更新使用 ID 索引和小响应。
- 会话只持久化人工状态；文件名的规范化路径+内容身份、内部精确源/内容/布局身份必须防止同内容不同路径串用。
- 只有通过完整 `saige-review-state/v2` 路径/内容/布局/item/历史校验的旧 `<source_hash>.json` 才迁移到新会话路径；迁移不删除共享旧文件。
- 损坏类别/状态/历史不得部分恢复；原子保存失败不损坏上一份会话文件。
- 目录修正版和覆盖在 shadow 上完成，严格检查路径/类别/数量/内容；中途失败不修改源。
- srproj 多处类别写回（含 9→10、99→100 的变长数字）只替换目标标量并一次拼接；DOCTYPE、根外/根内注释、处理指令、未知节点和混合内容必须逐字节保留。
- visionproj 修正版保持条目清单/顺序/目录标记、归档注释和关键元数据；manifest 之外每个条目的大小和内容 SHA-256 必须与源一致，截断或改字节必须阻断提交。
- 覆盖使用最终 source displacement，对被位移对象重验，失败可回滚，成功返回并保留 `recovery_copy`；备份名称不因同秒操作冲突。
- 默认端口被占用时回退到系统空闲端口；非“地址已使用”错误不得被吞掉。

## 合成错标排序验证

目的是隔离 DINOv2 推理，确认“分类器 + 近邻支持”的评分代码对一个明确错标有基本辨识度。该测试只需 NumPy 与 scikit-learn，不加载 Torch、transformers 或真实模型。

### 方法

1. 使用固定随机种子生成至少三个间隔明显、每类样本数足以做分层交叉验证的特征簇。
2. 正常样本标签与所属特征簇一致。
3. 选一个远离边界的样本，故意将其标签改成另一类。
4. 调用公开的纯特征评分入口，不做降维，不读图像。
5. 将全部样本按疑似错标分数降序排列。

### 预先定义的验收条件

- 被注入样本的 `suggested/predicted` 类别必须回到其真实特征簇类别；
- 被注入样本的疑似错标分数必须位于所有样本的前 5%（向上取整，至少 1 个位置）；
- 特征或标签包含非有限数、负类别 ID、行数不匹配或维度错误时必须明确失败。

仓库中对应的自动化用例应命名为 `test_injected_wrong_label_is_ranked_near_the_top` 或同等含义。文档仅定义方法和门槛；每次发布都应在当次测试报告中记录它是通过、失败还是跳过，本文不预先宣称结果。

## 真实项目 precision@K / recall@K 验收

该层才用来回答“人工查前 K 个时，能否比基线更快找到错标”。

### 1. 数据与真值

- 从真实生产分布中冻结一份只读项目副本，记录项目文件和引用图像内容指纹。
- 由至少一名不看模型分数的独立审核者建立 item 级错标真值；边界案例标为“不确定”并事先决定是否从主指标排除。
- 在结果冻结前，调参人员不得使用该验收集选配置或阈值。

### 2. 冻结运行身份

每次运行报告必须包含：

- 应用版本、Git commit（如有）、缓存 schema 和算法版本；
- 模型 repo + 完整 revision，当次 Hugging Face cache `config.json`/`model.safetensors` 各自大小和 SHA-256；或本地模型配置、所有权重/索引的大小和 SHA-256；
- Python、NumPy、Pillow、scikit-learn、Torch、transformers 和 umap-learn 版本；
- CPU/GPU 型号、CUDA 可用性、实际设备、数值精度和有效输入尺寸；
- 背景、ROI 外扩、mask pooling、投影与其他全部分析配置；
- 源/引用图像指纹、样本数、类别分布、真值错标数与排除的不确定数。

首次运行必须是空缓存；然后以同一身份重跑一次验证缓存命中的结果与排序一致。两次分别报告总时间、峰值内存/显存和缓存大小；同时记录特征/评分矩阵预估值，不把 512 MiB 保护预算当作实际峰值。

### 3. 预先冻结 K 与基线

K 是复查预算，必须在观察结果前决定。建议同时报告：

- 绝对预算：K = 10、25、50、100（不超过样本数）；
- 相对预算：K = 样本数的 1%、5%、10%（向上取整）。

至少包含两个基线：

1. 随机排序：使用固定的多个随机种子，报告均值和区间；
2. 原始/加载顺序：模拟没有模型排序时的当前流程。

如果业务已有旧排序器，也必须作为第三基线。

### 4. 指标

设排序前 K 个中真实错标数为 `TP@K`，全部可评估样本中真实错标总数为 `E`：

```text
precision@K = TP@K / K
recall@K    = TP@K / E
lift@K      = precision@K / (E / N)
```

主表对每个 K 报告模型、随机基线和原始顺序的 `TP@K`、precision@K、recall@K 和 lift@K。还应报告分类别指标，避免多数类的总量结果遮蔽少数类失效。

### 5. 验收决策

项目负责人必须在盲测前写下业务主 K 和最低可接受 precision@K/recall@K；阈值依错标基率和复查成本而定，本文不伪造通用数字。至少满足以下通用门槛才可声称“对该项目有排序价值”：

- 预注册主 K 的 precision@K 和 recall@K 达到预注册阈值；
- 主 K 上不低于原始顺序，并高于随机基线的预先规定上界/显著性判定；
- 没有预先定义的关键少数类回归；
- 无缓存与缓存命中运行在同一身份下给出相同的分数/排序；
- 人工复核所有前 K 样本，记录并分析高分假阳性。

如果真值错标总数 `E=0`，recall@K 无定义，该数据集不能用于验收错标检出能力。如果样本太少或类别不平衡使置信区间过宽，应报告“证据不足”，不应放宽阈值后宣布通过。
