# Saige标记复查工作台 v0.0.1 PRD

## 定位

Saige标记复查工作台是本地优先的标签质量复查 WebApp。它用 DINOv2 特征空间、邻域一致性和分类器建议帮助人工决定复查顺序。“疑似错标分数”是未校准的优先级信号，不是错误概率，不代替人工判断。

## v0.0.1 目标

1. 完整分开“数据已载入”与“模型已分析”，不在预分析阶段伪造分数或建议。
2. 将模型下载变成可见、可选和可审计的用户决定，并用完整 revision 固定默认模型。
3. 使分析缓存只在输入、模型、代码/算法、依赖与执行身份匹配时复用。
4. 使后台分析结果以一个验证后的原子批次写回，不与会话更新竞争。
5. 使目录与文件覆盖都在已验证 shadow 上完成，保留常规备份和提交级 `recovery_copy`。
6. 在不将整个数据集放入高频轮询响应的前提下，保持大数据集复查的可用性。

## 核心用户流程

1. 选择图片母文件夹、`.srproj`、`.visionproj` 或 Saige JSON；对项目目录外图像根做显式最小授权。
2. 在“尚未分析”状态检查源、类别和预览可用性。
3. 配置背景、尺寸、ROI 外扩、mask pooling、降维、设备和模型访问策略，然后运行分析。
4. 分析成功后，从高分项开始，在队列、分布图与详情之间联动复查。
5. 将项设为正确、已修改、不确定或跳过，并使用 Ctrl+Z/Ctrl+Y。
6. 默认导出修正版；仅在明确输入确认短语时覆盖源。
7. 重启后恢复人工复查会话，再次点击分析以恢复版本缓存中的分析结果。

## 功能需求

### 数据源

- 支持一级类别文件夹、Classification/Detection/Segmentation srproj、Saige IAD/OCR/Det/Rod/Seg JSON 与 visionproj。
- 文件夹指纹必须包含类别目录与图像内容，不能只依赖 size/mtime。
- srproj/Saige JSON 的分析输入身份必须加入引用图像的内容指纹，对重复引用去重读取，缺失图像也有确定身份。
- 预览路径必须位于默认源根或用户显式授权的额外根；绝对路径不自带授权。
- Saige JSON 和 visionproj manifest 必须以严格 JSON 读取：拒绝非有限数、数字溢出、任意层级重复键与过深嵌套；标注数字字段还必须单独验证有限性和边界运算不溢出。
- srproj 重复最终显示类别名，或 Saige 同名类别具有冲突 `classId`/`classColor` 时必须拒绝，不得猜测映射。
- 文件夹源的根图像，以及根目录内任意层级条目中的符号链接/Windows 目录联接和非普通文件系统对象必须拒绝。visionproj 重复归档名、带数据的目录条目或多个有效项目 manifest 也必须拒绝。

### 模型与分析

- 默认模型为 `facebook/dinov2-base@f9e44c814b77203eaa57a6bdbbd535f21ede1415`；非本地模型必须使用完整 40 位提交哈希。
- `setup.ps1` 默认显式预取约 350 MB 的权重；`-SkipModelDownload` 跳过预取，`-CpuOnly` 选 CPU PyTorch。
- setup 在安装标记中记录应用/清单、PyTorch 变体与 Hugging Face cache `config.json`/`model.safetensors` 的大小和 SHA-256；标记写入后必须执行完整依赖版本、导入、PyTorch 变体/GPU 与模型文件自检。自检失败必须删除标记。
- 运行时默认 `local_only`；只有用户在当次分析中选择 `download_if_missing` 才允许下载。
- Hugging Face 模型运行身份必须包含 repo、revision 以及当前 cache 中 `config.json`/`model.safetensors` 的名称、大小和 SHA-256；两者缺一或在加载期间变化必须失败。
- ROI 坐标必须验证有限性、方向和与图像的交集；无效 ROI 安全退化为整图，不产生空裁剪。
- 分析必须在模型加载前执行规模预检：float32 特征矩阵和评分工作矩阵各自使用 512 MiB 保护预算，并在知道实际特征维度后重验；`t-SNE` 最多 50,000 项，超限需改 UMAP 或拆分项目。限额不得描述成总 RAM/显存保证。
- worker 不得直接修改共享数据集；只能返回完整 `item_updates`，由服务端在锁内原子应用。
- 真实数据在分析成功前不显示分数或建议；演示数据必须明确标识合成结果。

### 缓存与会话

- 缓存键覆盖应用/算法/schema 版本、源和外部图像内容、原始标签、模型 revision 与实际配置/权重大小+SHA-256、关键依赖、实际设备/精度和语义配置。
- 缓存读、特征计算后与缓存写后都要重检输入内容；外部改动必须使本批失败。
- 自动会话只保存人工类别/状态和历史，不保存分析坐标、分数、建议或置信度。
- 会话文件名必须同时绑定规范化源路径和源内容指纹；会话内必须再校验精确源路径、内容指纹和布局指纹。保存为原子文件替换，恢复还必须验证状态、类别、ID 和 undo/redo 链。
- 旧的内容哈希命名会话只能在其内容已是完整 `saige-review-state/v2` 且路径/内容/布局全部匹配时迁移到新文件；不得删除共享旧文件或按文件名盲信导入。

### 用户界面与规模

- 列表、散点和详情必须双向联动；支持筛选、键盘导航和撤销/重做。
- 分析期间高频 `/api/job` 轮询不得返回全量 items；任务结束后才重新拉取会话。
- 散点范围计算必须迭代扫描，不将大数组展开为函数参数。
- 服务器仅绑定 loopback；指定端口被占用时回退到系统空闲端口。

### 安全导出

- 默认目标是新修正版；覆盖源项目必须使用独立 API 和精确确认短语。
- 导出前必须建立唯一命名的完整备份并验证。
- 文件与目录都必须在同卷唯一 shadow 上修改，严格复读后才提交；目录源不得就地移动。
- visionproj 导出必须保持条目清单/顺序/目录标记、归档注释和关键元数据，并对 manifest 之外的每个条目比对大小和内容 SHA-256，保证解压后逻辑负载逐字节一致。
- 覆盖提交必须先位移原源、重验被位移对象，再放入已验证产物。成功时保留并返回 `recovery_copy`；失败时尽力回滚。

## 验收标准

- 轻量 CI：Windows + Python 3.12，不安装 Torch、不下载模型，通过全部单元/集成测试、`compileall`、`node --check src/saige_reviewer/static/app.js` 和 PowerShell AST 对 `setup.ps1` 的语法解析。
- 合成排序门槛：在多个可分特征簇中注入错误标签，模型建议回到特征簇类别，且被注入样本进入疑似分数前 5%。该门槛仅验证评分代码，不是真实模型结论。
- 真实项目验收：用隐藏人工真值的错标集合报告 precision@K、recall@K、随机/原始顺序基线、模型 revision、依赖、设备、配置和源指纹；不得以“分析跑完”替代排序效果。
- 安全验收：默认导出不改源，备份与 shadow 严格验证，外部改动阻断写出，覆盖成功返回可保留的 `recovery_copy`。

## 非目标

- 不将疑似错标分数宣称为错误概率或自动正确答案。
- 不在无明确用户选择时下载模型。
- 不在会话 JSON 中复制版本化分析缓存。
- 不读取未授权的外部图像根。
- 不在本地 MVP 中实现团队审批流、远程同步或第三方任意 JSON 自动写回。
