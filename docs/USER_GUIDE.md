# Saige标记复查工作台 v0.0.1 用户指南

## 1. 安装与启动

系统要求是 Windows 与 Python 3.12 或 3.13，推荐 Python 3.12。首次双击项目根目录的 `Start Saige Reviewer.bat` 时，工作台会创建 `.venv`、联网安装分析依赖，并默认预取约 350 MB 的固定 DINOv2 权重。

若没有 NVIDIA GPU，建议先执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1 -CpuOnly
```

若安装当时不允许下载模型：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1 -SkipModelDownload
```

`-SkipModelDownload` 不代表整个安装离线：创建环境与安装 Python/PyTorch 依赖仍需要可用的包源。此选项只跳过权重预取。

默认安装会把 Hugging Face 缓存中 `config.json` 和 `model.safetensors` 的文件大小/SHA-256 记入 `.venv/.saige-reviewer-setup.json`。写入标记后，setup 会立即运行完整自检：核对应用和依赖清单、精确依赖版本、关键模块可导入性、CPU/CUDA PyTorch 变体，以及未跳过模型下载时的两个模型文件。失败时标记会被删除，启动器不会把该环境当作安装完成。`-SkipModelDownload` 不跳过依赖和 PyTorch 自检。

安装后可双击启动器，或手动运行：

```powershell
.\.venv\Scripts\python.exe run.py --open-browser
```

工作台默认请求 `127.0.0.1:8765`。如果 8765 已被占用，它会自动使用系统分配的空闲本地端口；以控制台打印并由启动器打开的实际 URL 为准。

## 2. 打开数据源

在顶部点“打开数据源”。可直接点“选择项目文件”从资源管理器选择 `.srproj`、`.visionproj` 或 Saige JSON，也可点“选择数据集文件夹”选择按一级类别分组的图像目录；完整路径输入框继续保留，便于粘贴路径。路径仅在本机使用，最近项目也只保存在本地工作目录。

默认只允许读取数据源所在目录及其子目录中的预览图。如果 srproj 或 JSON 引用了该目录之外的图像，请展开“外部图像目录”，用“添加目录”从资源管理器追加，或在输入框中显式填写根目录；多个 Windows 路径用分号分隔，例如：

```text
D:\images; E:\shared-images
```

只授权实际需要的最小根目录。项目文件中出现的绝对路径不会自动变成授权；未授权越界路径会被拒绝。

如果打开项目后才发现预览被阻止，可直接点击预览区中的“选择并授权目录…”：选择实际存放图像的文件夹后，工作台会保留当前复查会话、记录该授权并立即重试当前图和同类参考图，无需重新打开项目。

用 CLI 直接打开源时，可重复使用 `--image-root` 给出额外授权根：

```powershell
.\.venv\Scripts\python.exe run.py --source D:\data\project.srproj `
  --image-root D:\images --image-root E:\shared-images --open-browser
```

真实项目打开后，列表中的模型建议与疑似错标分数会显示为“尚未分析”/“—”。这是正常的：载入阶段不会伪造分数或模型建议。

工作台会拒绝语义不唯一或无法安全保真的输入：

- Saige JSON/visionproj manifest 中的 `NaN`、`Infinity`、数字溢出成的非有限值、任意层级的重复 JSON 键或过深嵌套；
- srproj 中重复的最终类别显示名，或 Saige JSON 中同名类别使用不同 `classId`/`classColor`；
- 图像文件夹根目录中没有类别归属的图像；
- 图像文件夹根目录内任何层级条目中的符号链接、Windows 目录联接或非普通文件系统对象；
- visionproj 里重复的归档路径、携带数据的目录条目，或同时存在的多个有效项目 manifest。

这些错误需在原项目或它的副本中消除歧义，不应通过放宽读取边界绕过。

## 3. 运行 DINOv2 分析

点“运行分析”，可配置：

- 背景：原始背景、灰度/弱化背景、标注外统一中性灰；
- 输入尺寸：自动、224、336 或 518；
- 降维：UMAP 或 t-SNE；
- 设备：自动（优先 CUDA GPU，显卡运行时不可用时从头改用 CPU）、仅 CUDA GPU 或仅 CPU；
- 模型访问：仅使用已安装模型（离线），或缺失时允许本次联网下载；
- ROI 外扩比例与 mask-pooled 特征。

自动尺寸在显存不少于 8 GiB 的 CUDA GPU 上选 518，其他可用 CUDA GPU 选 336，CPU 选 224。工作台使用 `facebook/dinov2-base` 的固定 revision `f9e44c814b77203eaa57a6bdbbd535f21ede1415`。

“自动”模式会先尝试 CUDA。若模型加载或推理发生显存不足、CUDA/驱动运行时错误，工作台会释放显存并从头使用 CPU 重试；完成提示会写明最终设备。显式选择“仅 CUDA GPU”时不会自动回退，便于需要严格控制执行环境的用户及时发现显卡问题。

默认“仅使用已安装模型”不会联网。如果权重缺失，开始按钮会保持不可用；运行 `setup.ps1` 预取，或在当次对话框中明确改为“缺失时允许本次联网下载”。

实际分析身份会包含当前 revision 的 Hugging Face 缓存 `config.json` 和 `model.safetensors` 各自的大小/SHA-256，而不只记录模型名称。两个文件不完整，或在模型加载期间发生变化，本次分析都会停止。

在加载模型前，工作台会拒绝明显超出规模保护预算的项目：

- float32 特征矩阵按每项 768 个数值估算，上限 512 MiB，并会按实际特征维度再检一次；
- 评分工作矩阵按“样本数 × 实际类别数 × 16 字节”保守估算，上限 512 MiB；
- `t-SNE` 最多 50,000 项；超限请选 UMAP 或拆分项目。

两个 512 MiB 值是主要矩阵的安全门槛，不代表分析总内存一定小于 512 MiB，也不是对物理 RAM/显存的可用量保证。

分析时顶部显示进度，打开源、人工状态更新与导出操作暂时禁用。任务完成后，整批结果才会一次性进入当前会话。

相同项目、原始标签、引用图像内容、模型、依赖、设备/精度与分析配置会复用版本化缓存。任一身份变化都会产生新缓存键。

如果 srproj/JSON 引用的外部图像在分析完成后被替换，工作台会在下一次预览时废弃整批旧分数、建议和散点坐标，自动刷新会话并保留一条提示，要求重新运行分析。人工复查状态不会被清除。

## 4. 复查

分析完成后，左侧默认按疑似错标分数降序排列。可按状态、类别、最低分数和文件名筛选。点列表或散点会同步选中；预览可切换 ROI 与原图。

特征分布图支持以指针位置为中心滚轮缩放、按住拖拽平移、点击散点选择项目；工具栏的 `−`/`＋` 可逐级缩放，“自适应”会复位视口并显示当前全部有效坐标。窗口或面板尺寸变化时，画布会保持当前中心与缩放比例并按高 DPI 重新绘制。图内状态栏会显示有效点、当前视窗点数，以及大项目是否使用性能抽样。

桌面宽屏下，“复查队列 / 特征分布 / 标注详情”之间有两条可拖拽分隔条。向左右拖动可把空间留给图像或特征图；聚焦分隔条后可用左右方向键微调，按 `Home` 或双击恢复该侧默认宽度。宽度会保存在当前浏览器中，下次启动自动恢复；窗口变窄时会自动限制侧栏，保证中间特征图仍可用。

标注详情中的图像预览区固定保持 4:3，因此加宽详情栏时，预览宽度和高度会同比增长。预览支持以光标为中心滚轮缩放、按住拖拽平移或点“自适应”复位；`−`/`＋` 按钮和键盘 `＋/－`、方向键、`0/F` 提供等价操作。“查看原图 / 查看 ROI”使用独立按钮，切换项目或模式时会自动恢复自适应视图。点“隐藏轮廓”可关闭 ROI 边框或多边形，按钮会变为“显示轮廓”；该状态会同步应用到待复查图、三张同类参考图和大图浏览器，切换时保留已有缩放与平移位置。所有图像区域都会以 `宽 x 高 pix` 显示当前实际载入的像素尺寸；ROI 模式显示裁剪后尺寸，原图模式显示原图尺寸。

点击待复查图或任一同类参考图会打开独立的大图浏览器。浏览器支持光标中心滚轮缩放、拖拽平移、双击/`0`/`F` 自适应、方向键平移，并可用顶部按钮或 `PageUp`/`PageDown` 在当前待复查图和最多 3 张参考图之间切换。

预览区右侧还会并排显示最多 3 张同类参考样本。参考样本来自当前数据集：人工标记为“正确”的项优先，其后优先显示疑似分数较低的项；它们用于帮助理解类别外观，但不是经过独立验证的标准答案。可从“选择参考类别”切换到任意类别；模型建议与当前类别不同时，还会出现“对照建议”快捷按钮。

- “标注正确”：保持当前类别并标记已复查；
- “保存修改”：把下拉框类别暂存到会话；
- “不确定”：留待其他人员判断；
- “跳过”：暂时略过。

方向键在特征空间中导航，J/K 按队列前后移动，Ctrl+Z/Ctrl+Y 撤销和重做。疑似错标分数只是优先级，最终结论必须由人工做出。

## 5. 会话保存与重启

`workspace/sessions` 仅持久化人工复查：修改后类别、复查状态与可验证的撤销/重做历史。模型分数、建议类别、散点坐标和置信度不保存到会话文件。自动会话文件名同时绑定规范化的源绝对路径和源内容指纹；文件内还绑定精确源路径、内容指纹与数据布局指纹。因此同一内容复制到另一路径时不会自动带入原路径的复查状态。

因此重启或重新打开项目后：

1. 已做的人工类别/状态修改会恢复；
2. 分析字段先回到“尚未分析”；
3. 再点“运行分析”，身份匹配时将命中 `workspace/cache` 中的版本缓存，无需重新提取特征。

不要手工编辑会话 JSON。格式、源指纹、类别、状态或历史链校验失败时，工作台会拒绝不安全的恢复内容。

如果 `workspace/sessions` 中存在旧的 `<source_hash>.json`，工作台只会在它本身是 `saige-review-state/v2`，且精确源路径、内容指纹、布局、item 和历史全部验证通过后，才把它安全迁移到新的路径+内容隔离文件。旧文件会保留；不要手动重命名它来强制迁移。

## 6. 导出与恢复

点“导出修正版”。推荐操作会在 `workspace/exports` 生成一个新项目，原数据不变。工作台会：

1. 重算源内容指纹；
2. 在 `workspace/backups` 创建唯一命名的完整备份并验证；
3. 在唯一 shadow/临时目标上应用修改；
4. 严格复读 item、类别、路径与图像内容；
5. 对 visionproj，保持 ZIP 条目清单/顺序/目录标记、归档注释和关键元数据，并将 manifest 之外每个条目的解压后大小与内容 SHA-256 同源归档比对；
6. 最后再次确认源没有被外部程序改动。

“覆盖原项目”位于折叠的危险操作区，必须输入 `OVERWRITE_SOURCE`。目录源也始终先在 shadow 上修改和验证，不会直接在源目录中移动图像。提交时工作台会先将原源位移到同级的唯一 `recovery_copy`，再放入已验证结果。

覆盖成功后，导出 API 结果中的 `recovery_copy` 指向被位移的原对象；常规 `backup` 则是导出前创建的完整备份。在人工验收新产物之前，两者都不要删除。若提交失败，工作台会尽力从 `recovery_copy` 回滚；错误信息指示人工介入时，先保留所有备份和位移副本。

默认工作目录：

- `workspace/exports`：修正版与手动导出的复查会话 JSON；
- `workspace/backups`：导出前的完整备份；
- `workspace/sessions`：自动保存的人工复查会话；
- `workspace/cache`：版本化分析缓存。

## 7. 操作建议

- 分析或导出期间，不要用其他程序修改同一源或引用图像。
- 为避免载入阶段耗尽内存，普通 JSON/srproj 最大 128 MiB；visionproj 单个候选 manifest 最大 16 MiB、候选累计最大 64 MiB。图像在解码前还会检查 64,000,000 像素上限；超限项目应拆分或缩小图像后再打开。
- `.visionproj` 可能很大；修正版、常规备份和 `recovery_copy` 可能同时占用磁盘。
- 覆盖前先在副本上跑通导出与恢复流程。
- 疑似错标分数未校准为概率；评估模型排序效果时使用 [VALIDATION.md](VALIDATION.md) 的 precision@K / recall@K 协议。
